# Agent Note: 能力卡片明确报告下一步操作

Status: implemented

[English](2026-10-16-capability-card-outcomes.md) | 中文

## 问题

更新列表把版本与操作分散展示，原始依赖错误也未说明当前插件是否发生变化。原生状态回声还会重复发布未变的界面状态。

## 决策

每个组件的简介、版本、进度、重试及重启操作统一放在响应式卡片中。准备完成不等于生效：待应用的卡片明确请求确认重启，只有启动确认后才报告成功。引擎管理能力不足显示本地化前提提示，而非引擎下载失败。原始错误保留在可展开详情中。页面控制器对校验后的能力状态消息去重，状态仍归框架 store 所有，执行仍归原生更新器所有。

## 考虑过的替代方案

**保留稀疏列表与全局底栏。** 列表滚动会把组件更新与重启操作分隔开，因此不采用。紧凑卡片让操作留在对应组件上。

**以原始错误作为主要引导。** 实现层错误不能解释是否生效或下一步安全操作，因此不采用。原始详情仍然保留，但不替代这些说明。

## 后果

卡片需要横向空间，所以窄屏使用单列。页面不会自动安装、重试或重启，这些操作仍需确认。

## 验证

桌面组合测试覆盖准备完成、失败、重试、生效、前提提示、确认及重复原生快照，收到更新通知不会发起下载。运行时包兼容检查及事务切换仍由原生更新器负责。
