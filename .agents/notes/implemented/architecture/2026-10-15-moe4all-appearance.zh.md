# Agent Note: MoE4All 桌面外观

Status: implemented

[English](2026-10-15-moe4all-appearance.md) | 中文

## 问题

独立桌面产品需要自己的配色，同时不能把插件隔离在已有主题和语言生态之外。明亮的按钮底色可能让继承的白色文字难以辨认，原生启动控件也需要与加载后的应用一致。

## 决策

四种内置配色覆盖语义 alias token，不针对每种颜色重写插件样式。MoE4All 设置选择器显示森林绿、黑色、灰色和白色；旧 id 仍有效。正文、说明、禁用状态和状态提示采用可读的语义颜色，有填充底色的控件使用配对的前景 token，不固定使用白色。主题对比度测试覆盖常规、hover、选中状态的表面和主按钮。

已有 locale 和 theme 服务拥有应用偏好。限定作用域的 WebView2 消息桥接把已解析的值同步到原生标题栏与启动缓存；缓存不替代 Host settings。监听器随主题插件生命周期释放。本地 profile 持久化偏好，远程浏览器偏好保留已有的进程内策略。

## 考虑过的替代方案

**原生壳与插件分别管理偏好**会让窗口出现混合语言和配色，并产生竞争的持久化规则。限定作用域的桥接保留已有服务的所有权。

**替换已有 light 和 dark id**会改变已有 profile 的含义。新增具名配色允许 MoE4All 选择器演进，而不使已有设置失效。

## 最终桌面迭代

语言、外观和更新操作移入设置，删除原生偏好工具栏与 WinForms 更新弹窗。四种配色标注明亮或暗色。“自动跟随系统”保留用户选定的暗色配色，明亮时使用白色，并在重启后保留。森林绿改用深灰表面与低饱和绿强调色。共享配色数据也用于插件加载前的阶段。WebView2 将偏好和实际外观同步到启动缓存。DWM 设置原生标题栏及尽力适配的选择器标题栏，不改系统设置或其他应用。启动、解压及失败采用内嵌 HTML；缺少 WebView2 时保留原生启动表面作为 fallback。

常驻的 `settings.notification` outlet 在设置关闭时仍可提示更新。其 controller 管理呈现与订阅释放；原生壳校验精确回环来源和固定命令集。PowerShell 继续负责 Agent 安装、数据保留及回退。检测不会安装；下载要求已有可用版本并由用户明确确认。进度可关闭后重新打开。验证覆盖畸形消息、确认、系统切换、持久化、组装后的插件对比度、原生 fallback/DWM 及内嵌页面尺寸；不声称完成整合发布包的更新安装测试。

能力中心在设置的「插件」与「MoE4All」之间呈现，自动更新通知使用共享的 DSH 页内 Modal，不再另开原生更新窗口。两个入口共用同一个 controller 与进程持有的快照，跟随当前语言和配色，下载或重启前均需确认。原生桥接只接受固定动作和有界的组件、版本标识，不接收任意进程或文件系统命令。精确到组件和版本的跳过选择会跨重启保留，仅抑制自动提醒，不隐藏后续版本，也不移除手动安装。插件准备、冷切换与回退属于 Agent 发行层，不交给自更新插件。普通浏览器不会获得这些桌面操作。

## 影响

真实桌面测试发现模型插件的旧版 popover 会遮挡更新 Modal。设置现将 overlay 通过 portal 挂到 document body 并标记所有权；插件仅在缺少此标记时启用旧宿主的顶层兼容 fallback。共享 Modal 位于设置之上，既保留旧宿主兼容，也避免首次引导期间出现看得见但点不到的更新控件。

使用 token 的第三方插件自动跟随配色；写死颜色的插件仍需自行核验。仅用于装饰性图表标记的固定类别颜色与文字颜色分开。修改不影响推理请求或引擎调度。验证包含偏好持久化、桥接生命周期和对比度测试，以及两种语言、四种配色的完整应用截图。
