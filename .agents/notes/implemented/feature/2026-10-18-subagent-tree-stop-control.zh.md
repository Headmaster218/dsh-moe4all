# Agent Note：从子代理树停止运行中的 child

Status: implemented

[English](2026-10-18-subagent-tree-stop-control.md) | 中文

## 问题

子代理目录能显示哪些 child 正在运行，但用户必须先打开 child 会话才能点击 Stop。因此目录只能观察，不能直接管理。

## 决策

仅在运行中的可继续 child 行显示紧凑 Stop 操作，并复用现有带地址的 `subagent.interrupt` RPC；不增加另一条取消路径、不停止 one-shot 任务，也不离开目录。该 RPC 只中断当前轮次，同时保留 child Activation 和排队中的后续消息。

中断请求被接受后刷新目录，并持续显示停止中状态，直到权威目录报告 inactive。拒绝或失败时，在对应行内展示错误。停止按钮会阻止事件冒泡，避免同一次点击同时打开 child。停止和停止中状态都有本地化的无障碍名称。

打开的目录还会汇总不间断子代理谱系中的运行后代数和已知累计 token 用量。该用量是会话历史消耗，不是实时吞吐。如果只有部分后代报告用量，总值前缀显示 `≥`；没有任何用量时显示不可用。

## 验证

组件测试验证准确的 parent/child 地址，并确认停止操作不会触发导航。运行时 session-service 测试覆盖 UI action 到 RPC 的桥接。插件包构建与相关定向测试通过。

## 模型体验

### 模型看到的内容

没有变化。从目录停止与会话中的 Stop 一样，调用用户授权的中断 RPC，不创建提示词或 transcript 事件。

### Token 影响

操作本身不消耗 token。已被当前轮次接收的工作不会重新入队；尚未处理的后续消息按现有中断契约保留。

### KV Cache 影响

没有变化。目录操作不修改提示词或缓存状态。
