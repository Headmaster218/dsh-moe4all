# Agent Note: 有界工作区概览与明确的文件和协议操作

[English](2026-10-27-agent-ux-clarity.md) | 中文

Status: proposed

## Problem

宽泛的工作区查看请求可能触发对被忽略依赖目录的递归扫描。本地 Markdown 链接即使指向成功文件操作已经记录的目标，也不可点击。适配器支持显式协议覆盖，但内置目录提供方只能通过文件选择协议。

## Proposal

源码草稿通过既有文件系统服务新增非递归 `list_directory`，提供可配置的返回条数及序列化字节上限，不改变读取或修改权限。提供方仍枚举全部直接子项，后端真正的分页不在本次范围。

已定稿的本地 Markdown 链接复用产出文件解析器，而不直接打开任意浏览器 URL。只有已记录文件能匹配，重名和不支持的 scheme 保持不可点击。这只是对[行内文件提及决策](../../implemented/feature/2026-08-07-web-inline-file-mentions.zh.md)的部分扩展，不改变产出文件归属或流式渲染器。

所有 pi-ai 路由均可显式覆盖协议，内置路由可取消覆盖恢复预设。Provider ID 和凭据引用保持不变。这部分调整[配置平面决策](../../implemented/architecture/2026-07-30-web-config-plane.zh.md)的精选字段范围，保留其设置归属和最小路径写入机制。

## Alternatives considered

仅靠提示词不能提供浅层目录操作。递归 glob 仍适合定向搜索，但不作为概览默认方案。任意 `file:` 导航会绕开属主视图的路径匹配；通过重命名提供方选择协议则会破坏既有路由及凭据引用。

## Acceptance criteria

验证包含单测、真实 Loader 回归、工具与配置生成目录、受影响的对话快照及组合后的客户端。未知链接拒绝、流式安全、路由身份和凭据隔离仍为必要条件。定向源码测试不能替代完整运行时验收。

## Risks

目录分页以位置为准，子项变化可能使位置移动。仅经 shell 创建、没有 mutation location 的文件仍不在链接解析范围。协议覆盖作用于该路由的全部模型，不会自动适配不兼容凭据或模型。
